# D03 — Garde sur les compilations MSBuild

Le scanner reçoit la Compilation du compilateur pendant un Rebuild réel des projets produit. Les références NuGet, conditions et global usings de MSBuild ainsi que les générateurs participent à cette compilation. Chaque projet doit émettre son inventaire ; une erreur de compilation, une erreur de l’analyseur ou un inventaire absent font échouer la commande. Les identifiants de documentation Roslyn relient les types de deux assemblies même lorsque la référence est une métadonnée. Le graphe évalué est inspecté transitivement. Les sources écrites portant un suffixe .g.cs restent analysées. Les sorties synthétiques sous obj participent à la compilation ; elles sont distinguées des responsabilités du code écrit.

La commande `python3 scripts/check-modules.py --matrix` a réussi et produit 75 couples. Les 7 fixtures de `python3 -m unittest discover -s scripts/tests -p 'module_boundaries_tests.py'` ont réussi. Elles exercent le type NuGet résolu, la condition NET10, l’alias de concret, la source suffixée .g.cs, la réflexion, le SQL qualifié, le cycle, la transitivité du client, un port valide et les erreurs du compilateur. La première exécution a révélé des accès que la garde antérieure laissait passer.

[transition.tsv](../../../scripts/architecture/transition.tsv) consigne 52 triplets fichier/type/ressource existants, datés et associés à une phase ou à un audit dynamique. Les dérogations C7 de module_rules.py demeurent en place pour les implémentations historiques. Les nouveaux accès détectés hors liste sont refusés. Les noms de table interpolés, SQL sans schéma ou méthodes de réflexion non cataloguées, les activations EF, XAML et les chargements natifs ne sont pas tous démontrables statiquement. La recette PostgreSQL et les tests négatifs demeurent indispensables. D03 est **partielle** pour l’objectif d’exhaustivité dynamique et de contrôle de toute la DI.

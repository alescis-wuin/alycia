# C1 — Contrôler les dépendances dans les assemblies existantes

Référence de travail `118c9186d08f731763ad583a4de4051e8512c716`. L’inspection initiale ne voyait aucune dépendance entre deux types de Chat.Infrastructure utilisant le même namespace. Les dossiers, les anciens fichiers racine et les exceptions de type sont désormais attribués aux 11 propriétaires de la garde. Les 75 relations dirigées de la référence incluent les ports et valeurs, les types de configuration, l’accès aux projets et la persistance. La sortie de `--matrix` en donne les noms.

| Contrôle exécuté | Résultat |
|---|---|
| Garde sur le produit | 13 projets inspectés, 11 propriétaires, succès |
| Fixtures Python exécutant la garde sur des sources et projets C# temporaires | 4 sur 4 réussies |
| Inférence appelle un lecteur documentaire sans import, dans le même namespace et la même assembly | Rejet avec le fichier, la ligne et la règle Inference → Documents |

| Interface métier exposant HttpClient, accès au contexte EF hors composition | Rejets distincts |

Les fichiers concernés sont `scripts/check-modules.py`, le lecteur et les règles dans `scripts/architecture/`, les fixtures dans `scripts/tests/module_boundaries_tests.py`, les guides d’architecture et de contribution. Aucun changement de code produit. La garde examine les références C# résolues vers les types produit et les imports techniques. La réflexion et les chargements dynamiques ne font pas partie de cette mesure.
